# Derived Grammars

This standalone package shows a Coder consumer opting into `@Isomorphism` and
`@Prisms`. Macro dependencies stay outside the Coder runtime package.

From this directory, run the executable and focused tests with Swift 6.4 and
the Xcode 27 beta toolchain:

```sh
swift run --disable-sandbox DerivedGrammarsExample
swift test --disable-sandbox
```

The package uses local paths to `swift-coder`, `swift-isomorphism-derivation`,
and `swift-prism-derivation`, so the example must remain at its checked-in path
inside the `swift-institute` workspace.

## User records

The record grammar is:

```text
name   = 1*(Unicode letter / space)
age    = 1*ASCII decimal digit
record = name "," age LF
```

Parsing retains the age token as `String` through the final LF. Only after the
complete record is consumed does the conversion require an `Int` in `0...130`.
Consequently, `Alice,999\nnext` fails with `invalidAge("999")` and leaves
`next`, while `Alice,999x` fails at the missing LF before age validation and
leaves `x`. `prefix` returns one record and its caller-owned remainder; `whole`
rejects any trailing input.

Serialization accepts nonempty names containing only Unicode letters or spaces
and ages in `0...130`. It emits ASCII digits and LF. Leading zero spellings are
accepted on input and normalized, so `Alice,0042\n` serializes as
`Alice,42\n`. Valid values round-trip through the canonical representation;
exact source spelling is not preserved.

The builder stores fields in `Pair<String, Int>`. An explicit total
`Pair<String, Int> ↔ (String, Int)` isomorphism bridges that safe storage to the
tuple representation generated by `User.isomorphisms.memberwise`. `User` has no
custom initializer; its `value(name:age:)` factory does not change memberwise
initialization.

## Tagged nodes

The node grammar uses explicit tags:

```text
digits = 1*ASCII decimal digit whose complete spelling fits a nonnegative Int
node = "leaf(" digits ")"
     / "pair(" digits "," digits ")"
```

An unknown tag is recoverable `rejected` input. Once `leaf(` or `pair(` has
matched, the branch is committed: missing payload punctuation or a closing
delimiter becomes `malformed`, while invalid numeric content remains
`invalidInteger`. For example, `leaf(42]tail` fails with `malformed` and leaves
`]tail`. Serialization always emits the canonical tags and decimal spelling;
negative payload values fail with `invalidInteger`.

`@Prisms @dynamicMemberLookup` supplies the case prisms and, for this copyable
enum, the explicit extraction shorthand `extract: \.leaf`. Noncopyable source
or payload types use the consuming `prisms.case.extract` form for one-way
extraction. That consuming operation does not provide borrowed serialization;
a noncopyable Coder case also needs the explicit borrowed `Fold` supplied with
its prism, as described in the core Coder guide.

## Derivation limits

`@Isomorphism` derives from explicitly typed stored instance properties in
declaration order. Static and computed properties are excluded. Custom
initializers, inferred stored-property types, property wrappers or attributes,
lazy storage, observers, non-identifier patterns, and initialized `let`
properties are diagnosed; those records must define their isomorphism
explicitly. Derivation does not infer grammar policy, validation, tags,
delimiters, or canonical spelling.
